# Uzum sehr — «Исполни мечту! Зажги огонь на ёлке»

Новогодняя благотворительная акция Uzum E-com и фонда ONA. Каждое детское желание — лампочка на 3D-ёлке: пользователь выбирает лампочку, закрепляет желание за собой и приносит подарок в офис.

Стек: Next.js, TypeScript, Tailwind CSS, React Three Fiber, Framer Motion, Supabase (Postgres, Auth, Storage, Realtime).

## Посмотреть локально

Настоящий Supabase не нужен: `scripts/local-supabase.mjs` поднимает ту же схему во встроенном Postgres (PGlite) и отвечает по тем же адресам.

```bash
npm install
```

```bash
npm run demo
```

Откройте http://localhost:3000. Письма не отправляются, код входа всегда `000000`.

| Роль | Почта |
|---|---|
| Super Admin | `admin@example.com` |
| Admin | `manager@example.com` |
| Пользователь | любая другая |

Админка: http://localhost:3000/admin. На ёлке 150 вымышленных желаний из `supabase/seed_demo.sql`. Данные лежат в `.local-supabase/`: удалите папку, чтобы начать заново. В демо счётчики обновляются опросом раз в 3 секунды, а не через Realtime.

## Запуск в продакшене

### 1. Supabase

1. Создайте **новый отдельный проект** на https://supabase.com. Лучше выбрать регион ближе к Ташкенту, например Франкфурт.
2. В SQL Editor выполните целиком `supabase/migrations/0001_init.sql`. Файл `seed_demo.sql` на боевом проекте не применяйте.
3. Назначьте первого администратора. Это можно сделать до его первого входа:
   ```sql
   insert into public.admins (email, role) values ('ваша@почта', 'super_admin');
   ```
4. **Authentication → URL Configuration:** укажите адрес сайта в Site URL и добавьте `https://ваш-сайт/auth/callback` в Redirect URLs.
5. **Authentication → Email Templates → Magic Link:** добавьте в письмо код, иначе в нём будет только ссылка. Например:
   ```html
   <p>Твой код для входа: <b>{{ .Token }}</b></p>
   ```
6. **Authentication → SMTP Settings:** подключите свой SMTP. Встроенная почта Supabase отправляет всего несколько писем в час, для акции этого не хватит.
7. По умолчанию войти может любой, у кого есть почта. Чтобы пустить только сотрудников, настройте ограничение по домену через Auth Hook `Before User Created`.

### 2. Сайт (например, Vercel)

Импортируйте репозиторий и задайте переменные из `.env.example`:

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project Settings → API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Project Settings → API |
| `NEXT_PUBLIC_SITE_URL` | адрес сайта |

### 3. Перед запуском

- В админке загрузите настоящие желания: раздел «Импорт» или «Желания».
- Проверьте срок брони и лимит на человека: раздел «Контент», блок «Ёлка и бронирование». По умолчанию 14 дней и 10 желаний.
- Проверьте на настоящем проекте вход по письму и обновление счётчика в двух окнах: в локальном демо их нет.

## Как устроено

- **Бронирование.** Функция `book_wish` выполняет условный `UPDATE ... WHERE status = 'free'`: из параллельных запросов проходит один. Второй рубеж — уникальный индекс на живую бронь желания.
- **Статусы.** `free` (лампочка тёмная), `booked` (лаймовая или фиолетовая, цвет выбирается автоматически), `fulfilled` (подарок передан, тёплый цвет). Бронь и переданный подарок считаются отдельно.
- **Срок брони.** Просроченные брони снимаются при следующем обращении к сайту, отдельный планировщик не нужен.
- **Обновление без перезагрузки.** Realtime слушает таблицу `site_pulse`, в которой нет личных данных, и сообщает клиентам об изменении. Раз в минуту работает запасной опрос.
- **Лампочки.** Номер `bulb_no` задаёт место на ёлке. Новое желание занимает первое свободное место.
- **Лёгкий режим.** Качество сцены подбирается под устройство и снижается, если падает частота кадров. Без WebGL показывается плоская ёлка, где каждое желание остаётся кнопкой.

## Данные детей

- Клиент не читает таблицы напрямую: только функции, которые отдают разрешённые поля.
- Фото лежат в закрытом бакете `wish-media`. Без отметки о согласии файл не выдаётся даже по прямому запросу, ссылки временные.
- Перед загрузкой фото пересобирается в браузере: удаляются геометка и метаданные. Имя файла случайное.
- Сайт закрыт от поисковиков (`noindex`) и встраивания в чужие страницы.
- Служебная заметка и данные пользователей видны только администраторам.
- Имя, возраст и ID публичны, как и задумано акцией: для детей лучше указывать псевдонимы.

## Роли

| Возможность | Admin | Super Admin |
|---|---|---|
| Желания, статусы, импорт, контент, контакты, пользователи | да | да |
| Журнал действий | нет | да |
| Назначение администраторов, выгрузка всех данных | нет | да |

Права проверяются в базе, а не только в интерфейсе. Последнего Super Admin снять нельзя.

## Резервные копии

- Ежедневные бэкапы платформы входят в тариф Supabase Pro.
- `.github/workflows/backup.yml` каждую ночь делает зашифрованную копию базы. Нужны секреты `SUPABASE_DB_URL` и `BACKUP_PASSPHRASE`, без них запуск пропускается. В `SUPABASE_DB_URL` укажите адрес Session pooler из Project Settings → Database: прямое подключение работает только по IPv6, а раннеры GitHub его не поддерживают. После настройки один раз запустите workflow вручную и проверьте, что копия расшифровывается. Схема `auth` в копию не входит, поэтому для полного восстановления нужны и бэкапы платформы.
- Раздел «Команда и данные» в админке выгружает всё в JSON. В файле данные детей, храните его только в защищённом месте.
- Файлы из Storage в эти копии не входят.

## Формат импорта

Excel (`.xlsx`) или CSV, шаблон скачивается в разделе «Импорт». Обязательные колонки: `ID подопечного`, `Имя`, `Возраст`, `Желание`. Необязательные: `Город`, `Описание`, `Согласие на фото` (да/нет). Импорт идёт целиком: при любой ошибке не создаётся ни одной карточки.
